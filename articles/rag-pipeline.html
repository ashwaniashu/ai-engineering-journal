RAG Pipeline Architecture: Retrieval, Context and Generation

A practical introduction to designing a retrieval-augmented generation pipeline, from document ingestion and chunking to retrieval, grounded generation, and evaluation.

AI Engineering Journal · Practical engineering guide

What is a RAG pipeline?

Retrieval-augmented generation (RAG) gives a language model relevant information from an external knowledge source at answer time. Instead of relying only on information encoded in model parameters, the application retrieves passages and includes them in the prompt. RAG is useful when answers must reflect private documents, frequently updated information, or sources that can be cited.

Typical architecture

  1. Ingest: load PDFs, HTML, files, or database records.
  2. Normalize: extract text and preserve useful structure such as headings, tables, page numbers, and source IDs.
  3. Chunk: split content into retrievable passages without losing essential context.
  4. Embed and index: convert chunks to vectors and store them alongside metadata in a search index.
  5. Retrieve: find candidate passages using vector search, keyword search, or a hybrid of both.
  6. Rerank and filter: reorder candidates and enforce metadata or access-control filters.
  7. Generate: provide the best evidence to the model and ask it to answer within that evidence.
  8. Evaluate: measure retrieval quality, answer correctness, groundedness, latency, and cost.

Chunking: start simple, then measure

Fixed-size chunks are a reasonable baseline because they are easy to implement and benchmark. Overlap can reduce the chance that a key sentence falls across a boundary, but excessive overlap increases index size and duplicate results. Structure-aware chunking can work better for manuals and policies because it preserves headings and sections.

Do not choose a chunk size based on a universal rule. Build a small evaluation set of realistic questions, compare chunking strategies, and measure whether the correct evidence appears in the top results.

Vector search, keyword search, or hybrid search?

  • Vector search helps match semantically similar wording.
  • Keyword search can be strong for exact terms, IDs, product codes, and rare phrases.
  • Hybrid search combines both signals and can improve coverage when queries mix concepts with exact identifiers.

When combining ranked lists, reciprocal rank fusion (RRF) is one common approach. A reranker can then score query-document pairs to improve the ordering of a smaller candidate set.

Minimal Python example

# Illustrative pseudocode: replace these functions with your chosen
# document loader, embedding model, and vector database.

documents = load_documents("knowledge-base/")
chunks = split_documents(documents, chunk_size=700, overlap=100)
index = build_search_index(chunks)

def answer_question(question):
    candidates = index.hybrid_search(question, top_k=20)
    passages = rerank(question, candidates)[:5]
    prompt = build_prompt(question, passages)
    answer = llm.generate(prompt)
    return {"answer": answer, "sources": [p.source for p in passages]}

This is a conceptual example, not a runnable library-specific implementation. Production code should include input validation, access-control filtering, exception handling, timeouts, logging, and tests.

How to evaluate a RAG system

Use a fixed set of representative questions with trusted answers and source documents. Track retrieval metrics such as Recall@k and MRR, then assess answer correctness and faithfulness to the retrieved evidence. Human review remains important: automated metrics can miss domain-specific errors and misleading citations.

Common failure modes

  • Text extraction loses tables, columns, or page relationships.
  • Chunks lack enough context to answer a question.
  • Retrieval finds similar passages but misses the exact evidence.
  • Prompt instructions do not prevent unsupported answers.
  • Evaluation data does not represent real user questions.
  • Retrieved content is shown without checking user permissions.
Engineering takeaway: RAG quality is not just a model choice. It is the combined result of data preparation, retrieval, ranking, prompting, access control, and evaluation.
